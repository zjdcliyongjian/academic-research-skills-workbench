## 1. 本阶段交付结果

阶段 1 已把“独立科研 Vault + Codex Desktop + Supervisor Skills”接成可运行的本地工作台，形成以下主链路：

1. 创建科研课题，并自动建立独立 Vault 项目目录。
2. 上传本地原始资料或登记网页来源，保留来源台账和文件 SHA-256。
3. 在界面中显式选择并运行当前阶段的科研 Skill。
4. 实时接收 Codex 输出、运行状态和工具审批请求。
5. 由用户允许或拒绝具体工具调用；拒绝单次调用不会误判整次研究任务失败。
6. AI 结果先进入草稿层，只有人工采用后才生成正式版本并推进研究阶段。
7. 导出中文、英文或双语 Markdown / Word 研究方案。
8. 从项目页一键打开对应的 Codex Desktop 任务。

## 3. 架构与数据边界

### 3.1 本地架构

- 前端：React + TypeScript + Vite。
- 后端：Node.js 本地 HTTP 服务。
- 控制数据：Node 内置 SQLite，记录项目、来源、运行、审批和反馈。
- 知识资产：独立 Vault 中的 Markdown、CSV、JSON、JSONL 和导出文件。
- Codex：通过官方 App Server 的稳定 `stdio://` JSONL 通道连接，不使用实验性 WebSocket。
- 桌面衔接：通过 `codex://threads/{thread_id}` 打开对应 Codex 任务。

官方能力边界参考：[Codex App Server](https://developers.openai.com/codex/app-server/)。

### 3.2 证据分层

每个课题采用以下约束：

- 原始资料进入 `02-sources/raw`，不覆盖原件。
- 网页地址在阶段 1 仅登记为来源记录，未抓取时明确标记为未核验。
- AI 输出先进入阶段草稿目录。
- 人工采用后生成带版本号的正式文件。
- 运行、版本、审批和 Codex 绑定分别写入 `99-system` 事件记录。
- Markdown 和来源台账可脱离工作台直接读取，避免数据被界面锁定。

## 6. 阶段 1 的明确边界

以下内容没有包装成已完成能力：

1. 网页 URL 目前只做登记，不自动快照、抽取正文或核验元数据。
2. 当前主验收集中在 Idea 评估；文献调研和论文蓝图已具备入口与 Skill 路由，但尚未用多个真实课题做规模化验证。
3. 阶段 1 支持 Markdown 和 Word，不含 PDF、BibTeX、LaTeX 或期刊模板导出。
4. 本地服务仅设计为回环地址使用，未实现多用户账户、远程访问或权限隔离。
5. App Server 对除命令审批之外的特殊交互请求仍需继续补齐更细的界面类型。
6. Word 生成器已通过本机视觉验收，但工作台暂未在每次导出后自动执行整套渲染检查。
