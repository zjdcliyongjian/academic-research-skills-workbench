# AI 科研副导师工作台｜阶段 2 总实施路线

## 1. 阶段划分

阶段 2 不按“再增加几个按钮”拆分，而按四个可以独立验收的科研闭环拆分：

| 阶段 | 名称 | 关键问题 | 核心交付 |
| --- | --- | --- | --- |
| 2A | 可信文献调研闭环 | 来源是否真实、可读、可定位、可核验 | 原文快照、正文抽取、元数据、证据卡、引用库 |
| 2B | 章节级写作闭环 | 蓝图如何变成受证据约束的章节 | 引言/章节草稿、章节版本、缺证据占位、逐章采用 |
| 2C | 图表与整稿生产闭环 | 文字、图表与整稿如何保持一致 | 润色版本、图表任务、Draw.io/预览资产、整稿装配 |
| 2D | 投稿审查与交付闭环 | 投稿前如何发现问题并形成可交付包 | 投稿前审查、修订门、审稿回应、BibTeX/LaTeX/交付包 |

## 2. 共同产品原则

1. 原始资料只读；快照、抽取文本和 AI 产物均保存为衍生层。
2. “系统已处理”“元数据已核验”“内容已核验”“结果已采用”是四种不同状态。
3. Skill 完成不等于正式成果；所有阶段继续复用阶段 1.5 的采用、驳回、要求修改和版本追溯机制。
4. 正式写作只能把已核验来源写成来源事实；综合判断、推断和未知项必须显式标注。
5. 不能绕过登录、验证码、付费墙或站点权限；不复用浏览器 Cookie。
6. 不伪造 DOI、作者、年份、页码、实验结果、图表数据、期刊格式或投稿动作。
7. 上游正式版本变化时，下游正式版本自动进入“需复核”，不静默沿用。

## 3. 连续主链路

`资料登记 → 安全获取/抽取 → 元数据确认 → 证据卡 → 深度调研 → 蓝图 → 章节写作 → 语言润色 → 图表生产 → 整稿装配 → 投稿前审查 → 修订确认 → 引用与交付包`

## 4. 实施顺序

1. 先扩展数据库和 Vault，使 2A～2D 共用统一的阶段、版本和工件模型。
2. 完成 2A 的来源处理、预览、核验和证据卡。
3. 接通 7 个后续 Skill 的工作台入口和正式版本状态机。
4. 增加章节/图表/审查工作区与阶段门。
5. 增加 BibTeX、LaTeX 等可追溯导出。
6. 执行数据迁移、单元测试、构建和隔离端到端验收。

## 5. 本轮边界

- 支持公开 HTTP/HTTPS 单地址获取，不做整站爬取。
- 支持文本型 PDF、DOCX、Markdown、TXT、CSV 和普通 HTML；扫描 PDF 的 OCR 延后。
- 内部引用采用结构化元数据，导出 BibTeX；本轮不做 Zotero 双向同步。
- 生成 LaTeX 源文件；只有本机存在 TeX 引擎时才编译 PDF，不把“生成 .tex”误报成“已生成 PDF”。
- 工作台不自动投稿、不代替作者发送审稿回复。
