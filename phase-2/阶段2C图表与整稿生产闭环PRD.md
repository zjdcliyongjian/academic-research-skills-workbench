# 阶段 2C｜图表与整稿生产闭环 PRD

> 文档状态：已授权实施  
> 版本：V1.0  
> 日期：2026-09-15

## 1. 目标

把章节版本、语言润色和图表任务组装为一致、可追溯的整稿，不让视觉美化掩盖数据和语义风险。

## 2. 主链路

`采用章节 → 运行论文润色 → 审查语义变化 → 采用润色版本 → 创建图表/Draw.io 任务 → 核对数据与标注 → 采用图表方案 → 装配整稿`

## 3. 功能范围

- 接入 `paper-polish`、`figure-designer`、`drawio-reconstruction`。
- 润色结果必须区分普通表达优化与可能改变原意的高风险修改。
- 图表任务输入必须说明图意、真实数据来源、目标尺寸和论文位置。
- Draw.io 重建任务必须保留参考图来源并生成可编辑文件与预览要求。
- 工作台统一展示文字生产和图表生产的运行、审阅、版本和文件路径。
- 采用的润色/图表方案形成 `production` 阶段正式版本。
- 整稿装配记录所使用的调研、蓝图、写作和生产版本 ID。

## 4. Vault 工件

- `07-writing/polish/` 润色草稿与正式版本
- `08-figures/source/` 原始数据或参考图
- `08-figures/drawio/` 可编辑图
- `08-figures/rendered/` PNG/SVG/PDF 预览
- `08-figures/reviews.jsonl` 图表审阅记录
- `07-writing/manuscript/` 整稿装配清单

## 5. 人工门

- G2C-1：潜在语义变化逐项确认。
- G2C-2：图表数据、坐标、单位、图例和统计口径由作者确认。
- G2C-3：参考图重建必须确认版权与复用边界。
- G2C-4：整稿装配清单确认后才进入投稿审查。

## 6. 验收标准

1. 三个生产 Skill 均可在工作台运行并进入通用审阅状态机。
2. 每个生产结果可追溯到输入运行和上游正式版本。
3. 图表任务明确显示“设计方案”与“已生成文件”的区别。
4. 缺少真实数据时不能生成带伪造数值的正式图表。
5. 采用后生成 `production-vNNN` 正式版本。
6. 写作或蓝图更新会使生产正式版本进入需复核。
7. 正式整稿装配不纳入未采用草稿。

## 7. 暂不包含

自动发明实验数据、替作者判断版权许可、复杂矢量图在线编辑器和跨设备协同。
