# 阶段 2A｜可信文献调研闭环 PRD

> 文档状态：已授权实施  
> 版本：V1.0  
> 日期：2026-09-15

## 1. 目标

把“上传文件或登记网址”升级为可验证的证据链：每一条来源都能看到原始副本或快照、抽取正文、元数据、内容哈希、核验状态、引用定位和失败原因。

## 2. 用户主链路

`上传文件/登记 URL → 点击处理 → 保存不可变快照 → 抽取正文 → 识别题名/DOI/年份 → 人工核验 → 建立证据卡 → 深度调研 → 人工采用调研版本`

## 3. 功能范围

### 3.1 来源获取与抽取

- 本地文件：PDF、DOCX、MD、TXT、CSV。
- 网络来源：公开 HTML 与直接 PDF URL。
- 网页保存原始响应快照、最终 URL、获取时间、MIME、大小和 SHA-256。
- HTML 使用正文阅读算法抽取；PDF 保留页码分隔；DOCX 保留段落顺序。
- 处理失败必须保存失败原因，并允许重试。

### 3.2 安全边界

- 仅允许 HTTP/HTTPS。
- 默认阻断 loopback、私网、链路本地地址和非标准端口，防止 SSRF。
- 限制重定向次数、响应大小、超时和 MIME 类型。
- 不绕过登录、付费墙、验证码，不读取浏览器 Cookie。
- HTML 预览只显示抽取后的纯文本，不执行来源脚本。

### 3.3 元数据与去重

- 元数据字段：题名、作者、年份、期刊/会议、DOI、来源 URL。
- DOI 精确匹配优先；其次为内容哈希；再用规范化题名+年份提示疑似重复。
- 自动识别只标为“待核验”；人工确认后才标为“元数据已核验”。
- 同一论文的预印本、会议版和期刊版通过版本关系关联，不直接删除。

### 3.4 证据卡

- 证据类型：`source_fact`、`synthesis`、`inference`、`unknown`。
- 审查状态：`pending`、`verified`、`rejected`、`conflicted`。
- 必填：主张、来源、定位信息；可选：短引文、备注、冲突组。
- 定位至少记录页码、章节或段落序号之一；保存短引文哈希以识别原文漂移。

### 3.5 引用库

- 内部保存结构化元数据；外部生成 BibTeX。
- 缺作者、年份或题名时明确标记不完整，不自动编造。
- 深度调研 Prompt 只把已核验证据作为来源事实，待核验条目单列。

## 4. 状态模型

来源处理状态：`registered → processing → extracted → metadata_pending → metadata_verified → content_verified`。

异常分支：`failed`、`conflicted`、`rejected`。状态不互相冒充：正文抽取成功不等于元数据或内容已核验。

## 5. Vault 工件

- `02-sources/raw/` 原始上传文件
- `02-sources/web-snapshots/` 网页或网络 PDF 快照
- `02-sources/extracted/` 可检索正文
- `02-sources/metadata/` 结构化来源元数据
- `02-sources/evidence-cards/` 证据卡 JSONL/Markdown
- `02-sources/citations/` BibTeX 与引用清单
- `03-notes/冲突与边界.md` 冲突与适用边界

## 6. 人工门

- G2A-1：用户主动点击“处理来源”后才联网。
- G2A-2：自动识别的 DOI、题名、作者和年份由用户确认。
- G2A-3：证据卡逐条或批量确认，AI 不自行把主张升级为已核验。
- G2A-4：调研报告通过阶段 1.5 审阅门后成为正式调研版本。

## 7. 验收标准

1. 文本 PDF 能抽取正文并保留页码标记。
2. DOCX/MD/TXT/CSV 能抽取正文且不修改原件。
3. 公开 HTML 能保存快照和纯文本正文。
4. 私网 URL、超大响应、重定向异常和不支持 MIME 被安全拒绝。
5. DOI/题名/年份能自动候选并由人确认。
6. 内容哈希相同的重复文件会提示，不静默覆盖。
7. 证据卡能追溯到来源与定位。
8. 冲突主张能够并列保留。
9. 失败状态在重启后仍可见并可重试。
10. BibTeX 不含系统虚构字段。

## 8. 暂不包含

扫描 PDF OCR、付费数据库登录、整站爬取、自动下载引用网络、Zotero 双向同步和全文翻译。
