# 阶段 2D｜投稿审查与交付闭环 PRD

> 文档状态：已授权实施  
> 版本：V1.0  
> 日期：2026-09-15

## 1. 目标

在投稿前形成一次可追溯的完整审查，把严重问题、修订决定、引用库和最终交付文件组织到一起；收到评审意见后继续使用同一证据链规划回应。

## 2. 主链路

`整稿版本 → 投稿前审查 → 严重问题分级 → 修改/豁免说明 → 人工采用审查结论 → 生成交付包 → 导入审稿意见 → 逐条回应策略 → 作者确认与提交`

## 3. 功能范围

- 接入 `pre-submission-reviewer` 和 `rebuttal-guidance`。
- 投稿前审查覆盖论证、方法、实验、引用、表达、格式和可复现性。
- 问题分级：阻断、重大、一般、建议；每项记录状态和处置说明。
- 审稿回应按评论逐条关联论文证据、拟修改位置、补实验需求和无法承诺项。
- 审查与回应均使用采用/驳回/要求修改状态机，阶段标识为 `review`。
- 导出 Markdown、Word、BibTeX 和 LaTeX；PDF 需要本机 TeX 引擎且编译成功。
- 交付清单记录所有有效正式版本、来源哈希、引用数量、导出时间和限制说明。

## 4. 投稿边界

- 工作台不登录投稿系统、不发送邮件、不点击正式提交。
- 不替作者接受审稿人要求，也不承诺未完成实验。
- 目标期刊格式未提供时，只输出通用结构并标记待适配。
- DOI/作者/期刊字段缺失时，BibTeX 保留待补，不猜测。

## 5. 人工门

- G2D-1：阻断和重大问题逐项处置后，审查版本才能采用。
- G2D-2：最终交付包由作者确认。
- G2D-3：审稿回应由作者确认事实、语气和承诺。
- G2D-4：任何对外投稿或回复动作都在工作台之外由作者完成。

## 6. 验收标准

1. 两个审查 Skill 可从工作台发起、恢复、审阅和采用。
2. 采用后生成 `review-vNNN` 正式版本。
3. 上游整稿变化使旧审查版本变为需复核。
4. BibTeX 来自已核验元数据，字段缺失可见。
5. LaTeX 源文件可下载、预览并包含正式版本溯源说明。
6. 没有 TeX 引擎时明确显示“未编译”，不声称生成 PDF。
7. 导出文件库能识别并预览/下载新增文本格式。
8. 整个项目重启后仍保留来源、证据、版本、审查和导出记录。

## 7. 暂不包含

自动投稿、邮箱发送、期刊账号管理、版面费支付、版权签署和无人值守审稿回复。
