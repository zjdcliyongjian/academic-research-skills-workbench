# 阶段 2B｜章节级写作闭环 PRD

> 文档状态：已授权实施  
> 版本：V1.0  
> 日期：2026-09-15

## 1. 目标

把已采用的论文蓝图转成可逐章审阅的写作任务，而不是一次性生成不可控的整篇论文。

## 2. 主链路

`采用蓝图 → 选择章节/Skill → 输入真实实验材料与限制 → 生成章节草稿 → 检查引用和待补项 → 采用/驳回/要求修改 → 形成章节正式版本`

## 3. 功能范围

- 接入 `intro-drafter` 和 `paper-writer`。
- 支持引言、相关工作、方法、实验、讨论、结论及自定义章节任务。
- 运行前显示已采用蓝图、已核验证据数量和仍缺资料。
- Prompt 明确禁止根据常识补造实验结果、样本量、指标和显著性。
- 输出中保留 `[待补证据]`、`[待补实验]`、`[待作者确认]` 等占位。
- 每个运行都有草稿、父版本、审阅决定、正式版本和修改链。
- 蓝图或调研正式版本变化时，写作正式版本变为“需复核”。

## 4. 数据与工件

- 阶段标识：`writing`。
- `07-writing/drafts/` 保存 AI 草稿。
- `07-writing/versions/` 保存人工采用版本。
- 版本记录关联 Skill、运行、章节、上游版本和内容 SHA-256。
- 章节采用可批量导出，但不得把待审阅草稿混入正式整稿。

## 5. 人工门

- G2B-1：蓝图未采用时允许试运行，但只能保存为草稿并显示风险。
- G2B-2：涉及真实实验结果的段落必须由作者确认。
- G2B-3：每个章节只有点击“采用”后才进入正式稿。
- G2B-4：语义修改通过后才能覆盖当前正式章节版本。

## 6. 验收标准

1. 两个写作 Skill 均可从工作台发起并实时查看。
2. 完成、失败、取消、重试和修改链与阶段 1.5 一致。
3. 写作结果支持采用、驳回和要求修改。
4. 采用后生成 `writing-vNNN` 正式版本及哈希。
5. 上游版本变化后写作版本标为需复核。
6. 正式导出只读取当前有效写作版本。
7. 没有真实实验数据时，Prompt 和界面均不得暗示已有实验结论。

## 7. 暂不包含

多人协同编辑、在线富文本编辑器、自动实验执行、自动生成无法核验的数据和期刊排版微调。
